# 知识库写法（knowledge/*.md）

这个目录放「她应该知道的作品资料」。**改完不用重启桥接**，下一轮对话自动生效
（模块会比对文件修改时间，变了就重新加载）。

> 本文件（README.md）不会被当成资料加载，放心写。

## 规则

| 写法 | 含义 |
|---|---|
| `# 标题` | 文档标题，只取第一个 |
| `## 名字` | 一个**条目**（通常是一个乐队/阵营/作品） |
| `### 名字` | 条目下的**角色** |
| `关键词：a, b, c` | 触发词，正文里不会出现。放在 `##` 或 `###` 标题下面一行 |
| 其它行 | 原样保留的正文（markdown 都行） |

标题里用 `（日文／罗马音／中文）` 这种写法，括号内的名字会自动变成别名：

```markdown
### 戸山香澄（Toyama Kasumi／户山香澄）
关键词：香澄, Kasumi, 卡丝米
- CV：愛美
- 担当：主唱 & 吉他
```

## 什么时候会被注入

1. **目录**：每轮都会带一份「有哪些条目、各有哪些角色」，让她知道自己知道什么；
2. **详情**：当前消息或最近 12 条往来里出现了上面任何一个关键词，就把对应角色的整段资料塞进去。

也就是说：不聊邦邦时，她基本不花上下文；一聊到「そよ」，そよ 的资料立刻到位。

## 注意

- **单字关键词慎用**。自动别名至少 2 个字，手写在「关键词：」里的单字会生效，
  但中文没有词边界——`心` 会命中「开心」、`巴` 会命中「巴不得」。
  代码里只对一串国名前置字（荷/波/乌/爱/芬…）做了保护，其余靠自觉。
  需要单字名时，改成「小睦」「灯酱」这种两字写法更稳。
- 一条资料别写太长，`maxChars`（config.json 的 `knowledge.maxChars`，默认 2500）是
  单次注入的**总上限**，超出的部分会被丢掉。
- 想加别的作品（原神、东方、某新番），在本目录新建一个 `.md` 按同样格式写就行。

## 相关配置（config.json）

```json
"knowledge": {
  "enabled": true,
  "dir": "knowledge",
  "maxChars": 2500,
  "maxSections": 6,
  "alwaysIndex": true,
  "historyLookback": 12
}
```

- `alwaysIndex:false` 可以关掉常驻目录（只在命中关键词时注入详情）；
- `maxSections` 限制一次最多注入几个角色；
- `historyLookback` 是回看最近几条消息来找关键词（只看当前这条会漏掉「她」这种指代）。
