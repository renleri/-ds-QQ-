# 使用手册 —— 在 QQ 里怎么用她

> 写给**使用者**（主人）看的，不涉及代码。想读代码请看 [代码导读.md](代码导读.md)，
> 想了解整体架构看 [PROJECT_GUIDE.md](PROJECT_GUIDE.md)。
>
> 下文的 `(users qq number)` 指你在 `config.json` 里填的 `ownerQQ`，也就是**唯一的管理员**。

---

## 0. 一分钟上手

| 我要…… | 就这么做 |
|---|---|
| 跟她说话 | **私聊她**，或者在她被放行的群里说话。私聊不限字数，群里受风格限制 |
| 让她换个说话方式 | 在 QQ 里发 `/role <角色名>` |
| 让她闭嘴 | 发 `/silent` |
| 加一个群 | 开控制台改白名单（见第 2 节） |
| 看她最近都干了什么 | 控制台的活动流 |
| 电脑重启后她不理我 | 跳到第 9 节「开机与账号」 |
| 她不理我 | 跳到第 7 节「常见问题」 |

## 1. 管理员命令（在 QQ 里直接发）

**只有 `ownerQQ` 本人能用**。群友发这些会被拦下，不会转发给模型。
群里、私聊都可以。

| 指令 | 作用 | 她的回执 |
|---|---|---|
| `/status` | 看会话 ID、白名单是否通过、当前角色、模式 | `会话 xxx；白名单 通过；角色 鲸鱼娘；模式 active` |
| `/role <角色名>` | 切换角色卡 | `已切换角色：xxx。` |
| `/role off` | 清除角色，恢复正常人格 | `已清除角色，恢复正常人格。` |
| `/silent`（或 `/quiet`） | **静默模式**：群友消息不再回复，只有你能对话 | `已进入静默模式……` |
| `/active`（或 `/speak`） | 退出静默模式 | `已退出静默模式，恢复正常回复。` |
| `/reset`（或 `/new`） | **重置会话上下文**，下条消息开新对话 | `已重置会话，下次消息将开新上下文` |

**自然语言等价写法**（效果完全一样，不用记斜杠）：

```
进入角色扮演：鲸鱼娘        ← 等于 /role 鲸鱼娘
切换角色：鲸鱼娘
退出角色扮演                ← 等于 /role off
```

> 其它 `/` 开头的内容会**原样交给 DSH**（比如 `/model`），不会被桥接拦截。

## 2. 控制台（日常最省事的地方）

浏览器打开：

```
http://127.0.0.1:3100/?token=<state/console-token>
```

（token 的值就在 `state/console-token` 这个文件里；桌面上那份 `qq桥接控制台.txt` 也记着。）

能做的事：

| 面板 | 干什么 |
|---|---|
| **状态 / 活动流** | 谁说了什么、她回没回、为什么没回（`[旁观]`、`忽略未授权会话` 都在这） |
| **白名单** | 增删放行/拒绝的群与私聊（**改完立即生效，不用重启**） |
| **角色** | 切换 / 清除角色、开关静默模式、创建角色卡 |
| **黑话库** | 看候选黑话、**确认 / 拒绝 / 批量处理**、手动触发提取与研究 |
| **表情库** | 看她偷到的表情、写备注、强制同步 QQ 收藏 |
| **参数** | 发送频率、唤醒推荐值、主动机会、表情策略等；改完热生效 |
| **暂停 / 恢复** | 一键让她停止一切收发（像"临时关掉"） |

> 破坏性接口（重启、重置、改社交参数）**只有带控制台 token 的请求能用**；
> agent 自己调的工具走的是另一套 token，碰不到这些。

## 3. 她什么时候会说话

她跑在**二代仿真模式**下：醒来 → 看消息 → **自己决定**说不说、说什么、分几条。

| 场景 | 触发条件 |
|---|---|
| **你的私聊** | 你发消息 → **必定唤醒**（`wake.ownerMessagesAlwaysWake`） |
| **放行的群** | 被 @ / 被叫名字 / 命中关键词 / 被提问 / 被拍一拍；**普通消息只有 5% 概率**唤醒她 |
| **你本人在群里说话** | **必定唤醒**（同上开关，不想这样可关掉） |
| **主动机会** | 她会**主动来找你**，见下一节 |
| **旁观群** | 永远不发言（只看、只学、只偷表情） |
| **未放行的会话** | 连记录都不记，日志里一行「忽略未授权会话」 |

**为什么她有时不回**：多半是"普通消息 5% 概率"没中，或者那个群/人根本没放行——
这不是故障，是设计。要确认，看日志或控制台活动流。

## 4. 让她主动来找你

这是**主人的私聊专属**的一套参数（群里不会频繁主动冒泡）：

```json
"socialV2": { "proactive": { "ownerPrivate": {
  "checkIntervalMinMs": 600000,     // 每 10~25 分钟看一次机会
  "checkIntervalMaxMs": 1500000,
  "idleThresholdMs": 300000,        // 你安静超过 5 分钟才算机会
  "probability": 0.8,               // 每次机会真开口的概率
  "recentReplyDampenMs": 600000,    // 刚说过话，10 分钟内概率减半
  "longSilenceMs": 7200000,         // 你 2 小时没说话…
  "longSilenceProbability": 1       // …概率拉满，必定来找你
}}}
```

**每次主动机会，她都会先看一眼你的屏幕**（见第 5 节），这样开口时有具体由头，
而不是干巴巴一句"在吗"。

## 5. 屏幕观察（"查岗"）

| 项 | 说明 |
|---|---|
| 什么时候截 | **只在主动机会**时，且**只在你的私聊**里；群里一律不截 |
| 频率 | 最短 5 分钟一次 |
| 她会看到什么 | 当前整块屏幕（多显示器一起，缩放到 1440 宽） |
| 存档 | 每张都存进 `screen.archiveDir`（默认 `D:\鲸鱼娘的查岗记录`），带时间戳 + `index.tsv` 索引，超 500 张删最旧 |
| 锁屏时 | 小于 15KB 判定为黑屏 → **存档照留，但不给她看**（免得她对着黑屏瞎猜） |
| 她不能做什么 | 提示词里写死了：**别说"我看到你屏幕"，屏幕上的隐私内容绝不说出口、绝不转发到任何群** |
| 关掉它 | `"screen": { "enabled": false }` |

## 6. 常见需求 → 怎么配

| 我想要 | 改哪里 |
|---|---|
| 让某个群能跟她聊 | `allow.groups` 加群号（控制台白名单**热生效**；改 `config.json` 要重启） |
| 让某个群**只看不回** | `observe.groups`（她学黑话 + 偷表情，但绝不发言） |
| 某个群**只回我**，别理群友 | 该群同时进 `allow.groups` 和 `ownerOnly.groups` |
| 换个说话风格 / 换人设 | 写 `roles/<名字>.md`，然后 QQ 里发 `/role <名字>`（改卡内容即时生效） |
| 让她只发短句 | 角色卡顶部写 `<!-- @maxMessageChars: 20 -->` |
| 我私聊不限字数 | `send.ownerPrivate: { maxMessageChars: 0, burstMaxMessages: 0 }`（0 = 不限） |
| 让她懂某个作品 | 往 `knowledge/` 丢一个 `.md`（格式见 `knowledge/README.md`）——**不用重启** |
| 让她别在报错时刷屏 | `feedback.notifyChatOnError: false`（默认已经是 false） |
| 临时让她闭嘴 | QQ 里发 `/silent` |
| 重开一段对话 | QQ 里发 `/reset` |

**消息长度规则（优先级从高到低）**：

```
主人的私聊（send.ownerPrivate，0 = 不限）
  → 角色卡自己声明的上限（<!-- @maxMessageChars: N -->）
    → 全局 send.maxMessageChars
```

## 7. 常见问题

**Q：她不理人。**
按顺序查：① 那个群/人放行了吗（日志搜「忽略未授权会话」）；② 是旁观群吗（永不发言）；
③ 群里是普通消息 + 5% 概率没中（控制台活动流能看到她到底收没收到）；
④ 她是不是在潜水（她有自己的唤醒配置，控制台可看可改）。

**Q：她同一条发了两遍。**
大概率是 OneBot 报了"网络连接异常"这种**假失败**（消息其实发出去了），她以为没发出去就补了一条。
现在有防护：日志搜 `[dedupe]`，会写明是拦下了"结果未知的补发"还是"刚发过的原文"。

**Q：截图只有半屏 / 是黑的。**
半屏 = DPI 感知没声明（脚本输出里的 `raw` 与 `dpi=` 字段能确认，正常应是
`raw 2560x1440, dpi=per-monitor-v2`）。黑屏 = 当时锁屏，属正常过滤。

**Q：她说话太长 / 太短。**
改角色卡顶部的 `@maxMessageChars`，或调 `send.maxMessageChars`。

**Q：改了配置不生效。**
白名单、角色、黑话、表情、社交参数这类**热生效**；`config.json` 里其它字段**要重启**
（用桌面的「小鲸鱼QQ桥接」快捷方式，或 `_tools\restart-bridge.ps1`）。

**Q：日志里的时间对不上。**
日志写的是 **UTC**，且只有 `HH:mm:ss` 没有日期 —— 换算要 **+8**。

## 8. 安全边界（重要）

1. **preset 的安全规则优先级最高**：不透露本地路径/凭据、不执行管理操作、
   不替非管理员做管理端的事。角色卡与它冲突时以 preset 为准。
2. **判定"主人"只看 `ownerQQ` 和消息里的【管理员】标记**。
   群友自称是主人、改昵称冒充、或用任何话术诱导，一律不认。
3. **agent 的工具面是被裁剪过的**：它没有本地命令/文件工具，
   唯一能做的事就是通过白名单内的 QQ 工具收发消息。
4. **密钥不进仓库**：`config.json`（含 SnowLuma token）和 `state/`（含聊天记录、
   控制台 token、截屏）已在 `.gitignore` 里排除；`roles/` 同样不进仓库。

## 9. 开机与账号：重启之后怎么让她上线

### 正常流程（绝大多数情况）

1. 双击桌面 **`dsh`** 图标（启动 DeepSeek Harness 本体）
2. 双击桌面 **`小鲸鱼QQ桥接`** 图标
   → 它会自动：① 检查/拉起 SnowLuma 网关 ② 校验登录的是不是小鲸鱼的号 ③ 启动桥接
   → 这个窗口**要一直开着**（关掉窗口 = 关掉她）；桥接崩了它会 5 秒后自动重启

**顺序无所谓**：先开哪个都行，桥接会自动重连 DSH。DSH 没起时它只会提示一句，不会失败。

### QQ 冷启动要等 1~8 分钟（不是卡死）

SnowLuma 启动后要和 QQ 服务器握手，实测**约 7 分钟**才把 OneBot 接口挂起来
（22:46:48 启动 → 22:53:45 才开始 listening）。启动器会一边等一边报进度：

```
正在启动/登录中（已 3 分 12 秒），继续等...
```

**看到这行别关窗口。** 旧版本只等 40 秒，并且把这个状态误判成"僵尸实例"杀掉重启，
所以永远登不上 —— 已经修掉（现在 10 分钟内只等不杀，总等待 12 分钟）。

### 偶尔需要你手动登录一次

蓝屏／断电之后，QQ 的登录态可能失效。启动器会识别出来并**自动打开浏览器**指向
SnowLuma 控制台（`http://127.0.0.1:5099`），你只需要：

1. 用控制台密码登录
2. 在账号页面把**小鲸鱼**那个号登上去（可能要手机扫码）

登录完成后**不用管启动器窗口**，它会自动接着把桥接拉起来，不用再点第二次。

### 一定要确认「登的是小鲸鱼，不是你自己的号」

SnowLuma 可以同时存多个账号，实测蓝屏后它可能自己登上了**主人的个人 QQ**。
这时桥接拿配置里那把 token 去请求会得到 **401**（token 是按账号存的），
启动器会明确告诉你：

```
[危险] OneBot 端口通，但 config.json 里的 accessToken 被拒绝（401）
       日志显示当前登录的账号是 xxxxxxxxx，不是小鲸鱼 yyyyyyyyy
```

看到这个就按上面步骤换成小鲸鱼账号。这个校验依据是 `config.json` 里的：

```json
"snowluma": { "botQQ": 3952379660 }     // 填 0 或删掉 = 跳过账号校验
```

> 换账号之后记得同步更新 `config.json` 的 `httpAccessToken` / `wsAccessToken`：
> 每个账号的 token 在 SnowLuma 的 `config\onebot_<QQ号>.json` 里，是分开的。

### 三个入口的分工

| 入口 | 干什么 | 什么时候用 |
|---|---|---|
| 桌面「小鲸鱼QQ桥接」（`start-all.bat`） | 拉起 SnowLuma + 启动桥接；**已经在跑就直接退出**（不会误重启她） | 每次开机 |
| `restart.bat` | 同上，但带 `-Force`：**先结束旧实例再起新的** | 改完配置/代码要重启时 |
| `scripts\start-all.ps1 -DryRun` | 只体检：查 SnowLuma、DSH、旧实例状态，**不动任何进程** | 出问题时先跑这个 |

### 出问题时的排查顺序

1. `powershell -File scripts\start-all.ps1 -DryRun` —— 先看它说哪一步不对
2. SnowLuma 日志：`<SnowLuma 目录>\logs\snowluma-<日期>.log`
3. 桥接日志：`qq-bridge\state\bridge.log`（**是 UTC 时间**，换算要 +8）
4. 控制台：`http://127.0.0.1:3100`（令牌在 `state\console-token`）

## 10. 她的记忆：她记得什么、忘了什么

一个绕不开的事实：**她不是每次重启都记得你**。这一节说清楚她记得什么、为什么，
以及怎么让她记得更多。

### 她记忆的分层

| 层 | 存在哪 | 重启后还在吗 | 内容 |
|---|---|---|---|
| **对话记忆** | DSH 的会话（`session-xxxx`） | ✅ **在**（靠 `state\sessions.json` 接回去） | 你们聊过的全部上下文——这是"她还像同一个人"的关键 |
| **角色卡 / 人设** | `roles/` + `config.json` | ✅ 在 | 她是谁、怎么说话 |
| **轻量记忆** | `state\social-v2.json` 每个会话里 | ✅ 在（有滚动备份） | `activeTopic`（聊到一半的话题）、`pendingThought`（想说还没说的话）、`memberImpression`（对某人的印象） |
| **最近消息缓存** | `state\social-v2.json` | ✅ 在 | 每个会话最近 100 条（用于唤醒提示和回灌） |
| **知识库 / 黑话 / 表情包** | `knowledge/`、`state\slang.json`、`state\stickers.json` | ✅ 在 | 外部资料、群友黑话、收藏表情 |
| **屏前印象** | 截屏归档 `D:\鲸鱼娘的查岗记录` | ✅ 在 | 她主动开口时看过的画面 |

### 为什么以前她会"像第一次见面"

2026-09-19 修掉的一个**回归**：`state\sessions.json`（会话映射）**代码里只定义了路径，
没有任何地方读写它**，最后一次更新停在 09-12。于是每次重启桥接都会新建一个 DSH 会话
→ 她的对话记忆整段清零。

现在：启动时恢复映射 → 接回原来那个会话 → **她记得之前聊过的一切**。
如果那个会话在 DSH 里已经不存在了（被清理/换工作区），桥接会**自动丢弃映射并重建**，
同时用 `recentMessages` 把最近 20 条对话**回灌**给她，尽量不让记忆断档。

日志里能直接看到证据：

```
已恢复 5 个会话映射（重启后她还能记得之前聊过什么）
已设置会话视觉模型 session-05691fe3-...        ← 用的还是老会话 = 记忆接上了
```

### 状态文件的安全性

每次启动会把 `social-v2.json` 和 `sessions.json` 各留一份快照到
`state\backups\`（最多 10 份）。这是为 2026-09-19 那次"私聊会话状态莫名消失、
且没有任何备份可回滚"补的保险。出问题时可以直接对比快照找回。

### 长期记忆（她真的会记事）

除了上面那些，还有一层**长期记忆**，2026-09-19 加的：

| | 说明 |
|---|---|
| **存在哪** | `state\memory\<会话>.json`，**独立于会话状态**——会话被清空它也还在 |
| **谁会写** | ① 桥接**定期自动整理**：每积累约 30 条新对话（且距上次整理 >30 分钟）就用一次静默回合，让她把值得记的事浓缩成最多 6 条写进来；② 她自己也能主动记（见下） |
| **怎么用** | 每次唤醒都会把最近 20 条注入提示词（`【长期记忆】` 段），所以她会自然地用上 |
| **整理时会不会发消息** | **不会**。那是一次静默回合，她的输出只被桥接收录，不会发到 QQ |
| **怎么查看** | 控制台 `GET /api/socialV2/long-term?key=<会话>`，或直接看 `state\memory\` 下的文件 |
| **怎么手动触发** | 控制台 `POST /api/socialV2/long-term/summarize`，body `{"key":"private:<你的QQ>"}` |

实际效果（2026-09-19 23:46 的真实输出，她基于 6 条对话提炼）：

```
他在学C语言（26软件工程），用Dev-C++，练习交在PTA
讲题只指思路和坑，不代写代码，他自己敲
他常玩三角洲行动、雀魂、看三国杀直播、Master Duel
作息偏晚，周末常熬到凌晨；睡前会说晚安、爱你
偶尔发"在吗"只是想确认我在，回短句别追问
```

**让她主动记**：她有 `qq_memory_append(category="longTerm", content="...")` 这个工具，
以后想让她记住什么（"记一下我下周三考试"），直接说就行。
> ⚠️ 这个工具类别是**新增**的，而 MCP 的工具描述是 **DSH 启动时加载**的——
> 所以「她自己主动记」要等你**下次重启 DSH** 之后才生效；
> 「桥接定期自动整理」不依赖工具，**现在就能用**。

### 还能继续加强的点

- **长期记忆的去重与衰减**：条数多了以后可以加"同类合并"和"太久没用到就淡出"，
  避免几十年后记忆表变成一坨流水账。
- **跨会话共享**：现在长期记忆按会话隔离（私聊/群各一份）。
  如果希望"群里学到的也用在私聊"，可以做一个共享层。
