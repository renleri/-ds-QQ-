## 0. 仓库里有什么、没有什么

| | 内容 |
|---|---|
| **有** | `src/` 全部源码、`scripts/` 启动与测试脚本、`dsh/` agent preset、`plugins/` 控制台插件、`knowledge/` 作品知识库、`public/` 控制台前端、`config.example.json`、README/文档 |
| **没有** | `node_modules/`（依赖，`npm i` 自己装）、`config.json`（**含真实密钥**）、`state/`（**运行时隐私数据**）、`roles/`（**私人角色卡**） |

### 为什么 `config.json`、`state/`、`roles/` 不在仓库里

这三个是**刻意排除**的（`.gitignore` 里也写死了）：

- `roles/` —— 角色卡是**私人内容**：里面写着主人是谁、QQ 号、称呼和相处方式。
  桥接启动时会从这个目录读卡，但**卡本身不该进公开仓库**。
  自己写卡时照着 `roles/README.md` 的格式放进本地目录即可（也不会被提交）。

- `config.json` —— 里面有 SnowLuma 的 `httpAccessToken` / `wsAccessToken`，
  拿到它就能操控你的 QQ 机器人。**第一次跑请自己复制**：

  ```powershell
  Copy-Item config.example.json config.json
  # 然后填入自己的 SnowLuma token、ownerQQ、白名单
  ```

- `state/` —— 运行时数据，含量不小且都是隐私：
  - `console-token`：控制台访问令牌
  - `social-v2.json`：**聊天记录**、每个会话的 agent token、唤醒配置、轻量记忆
  - `slang.json` / `stickers.json`：她学到的黑话、偷来的表情
  - `bridge.log` / `qq-activity.log`：运行日志（含聊天内容）
  - `screen.jpg`：**主人屏幕的截图**

  > 屏幕截图的长期存档默认写在 `D:\鲸鱼娘的查岗记录`（见 `screen.archiveDir`），
  > 同样不属于仓库内容。

| `mcp-host-server.js` | 宿主类工具（会话/进程控制等），进程控制默认关闭 |
| `mcp-web-search-safe.js` | 安全的联网搜索/抓取工具 |

| `sensitive.js` | 敏感信息正则（本机路径、凭据），命中的回复会被硬性拦下 |
| `safe-fetch.js` | 受限联网取图（防 SSRF、限大小、校验图片字节） |
| `forward.js` | 合并转发消息的解析与格式化 |
| `md-to-plain.js` | Markdown → QQ 纯文本，长文分条 |

| `self-test.js` | 自测（不需要 SnowLuma / QQ） |

### `dsh/agent-presets/` —— 给 QQ 会话用的 agent preset

| 路径 | 作用 |
|---|---|
| `qq-chat/` | 一代模式（closed-agent）：文本自动转发，工具面最小 |
| `qq-chat-v2/` | **二代仿真模式（reserved2）**：文本不自动转发，必须调发送工具；唤醒由她自己用 `qq_set_wake_config` 控制 |
| `*/qq-tool-restrict.mjs` | 工具白名单兜底：隐藏开发/管理工具，执行期拒绝白名单外的调用 |

> 两者冲突时**以 preset 的安全规则为准**。

## 2. 聊天功能

### 2.1 一条 QQ 消息的完整旅程

```
QQ 用户发消息
   │
   ▼
SnowLuma（OneBot v11 网关，本机 3000/3001）
   │  WebSocket 事件
   ▼
bridge.js  handleIncoming()              ← 所有入站消息的总入口
   │
   ├─ ① 分流判断（顺序很重要）
   │     旁观群？      → handleObservedGroupMessage()：入库+学黑话+偷表情，然后 return
   │     在 allow？    → 继续
   │     不在 allow？  → 记一行日志丢掉
   │
   ├─ ② 唤醒判定 evaluateWakeTriggerV2()
   │     @ / 叫名字 / 关键词 / 提问 / 拍一拍 / 概率
   │     主人自己在群里说话 → 必唤醒（wake.ownerMessagesAlwaysWake）
   │     都没命中 → 不投递（这就是「她有时不回」的正常原因）
   │
   ├─ ③ 组装 prompt：buildWakePromptV2()
   │     角色卡 + 会话令牌 + 反 AI 味 + 表情策略 + 记忆 + 当前唤醒配置
   │     + withSlangContext()：时间 + 黑话表 + 作品知识
   │     + 可选：屏幕截图（仅主人的私聊、仅主动机会时）
   │
   ├─ ④ 投递 deliverPromptNow() → DSH session.prompt
   │
   ▼
DSH agent（跑 preset：qq-chat-v2）
   │  她思考 → 调 MCP 工具发消息
   ▼
mcp-snowluma-safe.js → bridge.js 的发送端点
   │  （统一发送 / 分条发送 / 拍一拍 / 发表情）
   ▼
OneBot HTTP API → QQ 群/好友
   │
   ▼
bridge.js  pumpMux() 收到 turn/end → 收尾（记录、调度回复检查、防「永眠」提醒）
```

### 2.2 四种会话的可见性

| 模式 | 配置项 | 她能看到 | 她能回话 |
|---|---|---|---|
| 正常放行 | `allow.groups` / `allow.private` | ✅ | ✅ |
| 群主专属 | 放行 + `ownerOnly.groups` | ✅ | 只回主人，其他人只旁观 |
| 旁观（窥屏） | `observe.groups` | ✅（入库+学黑话+偷表情） | ❌ 对谁都永不发言 |
| 未放行 | 不在任何名单 | ❌ 只记一行日志 | ❌ |

### 2.3 发送侧的三道闸门

所有出站消息（无论走哪个工具）都会过：

1. **字数/条数上限** —— `effectiveMaxMessageChars()` / `effectiveBurstMaxMessages()`
   优先级：**主人的私聊**（`send.ownerPrivate`，0 = 不限） → **角色卡声明**
   （卡顶部 `<!-- @maxMessageChars: N -->`） → 全局 `send.maxMessageChars`
2. **重复发送保护** —— `duplicateSendBlock()`
   - 刚因网络错误失败过（结果未知）的同文 → 拦下，让它先翻聊天记录
   - 刚发成功过的同文 → 拦下
3. **敏感信息 + 频率** —— `sensitive.js` 命中本机路径/凭据直接不发；
   `maxSendPerMinute` / `maxSendPerHour` 限频

### 2.4 关键函数速查（都在 `src/bridge.js`）

| 函数 | 干什么 |
|---|---|
| `handleIncoming()` | 入站总入口，分流、唤醒判定、组装提示 |
| `deliverPromptNow()` | 投递 prompt（支持带图片） |
| `withSlangContext()` | 统一注入时间/黑话/知识 |
| `pumpMux()` | DSH 事件流处理（turn 结束、出错、提问） |
| `sendMessagesV2()` / `onebotSend()` | 底层发送 |
| `getSocialV2State()` / `appendSocialV2Message()` | 会话状态与消息入库 |

> `src/bridge.js` 文件头有完整的**功能索引**（含行号），先看那里。

## 3. 截屏功能

让她在「主动来找主人说话」之前，先看一眼主人在干什么——这样开口时有具体由头，
而不是干巴巴一句「在吗」。

### 3.1 什么时候会截

```
主动机会触发（proactiveCheck）
   ├─ 允许截吗？  screenAllowedFor()   ← 默认只允许主人私聊，群聊一律 false
   ├─ 距上次够 5 分钟吗？  screen.minIntervalMs
   └─ 起 PowerShell 跑 scripts/capture-screen.ps1
```

**不是一直在截**：只有「主动机会」这一条路会截，而且只发生在主人的私聊里。

### 3.2 脚本内部（`scripts/capture-screen.ps1`）

1. **先声明 DPI 感知**（Per-Monitor V2）
   > 不声明的话，2560×1440 的屏在 150% 缩放下只会量到 1707×960，
   > `CopyFromScreen` 就只抓到左上角一块——表现是「截图只有半屏」。这是踩过的坑。
2. 量虚拟桌面尺寸 → `CopyFromScreen` 抓全屏
3. 等比缩到 `screen.maxWidth`（默认 1440）
4. 存 JPEG（`screen.quality`，默认 60）
5. 输出一行带证据的结果：`OK <路径> 1440x810 (raw 2560x1440, dpi=per-monitor-v2)`

### 3.3 截完之后（`captureScreen()` / `archiveScreenShot()`）

| 顺序 | 动作 |
|---|---|
| 1 | **归档**：带时间戳复制到 `screen.archiveDir`（默认 `D:\鲸鱼娘的查岗记录`），追加 `index.tsv`，超过 `archiveMaxFiles`（默认 500）删最旧 |
| 2 | **锁屏过滤**：文件小于 `minUsefulBytes`（默认 15KB）判定为锁屏黑屏 —— **存档照留，但不附给她** |
| 3 | **附进 prompt**：作为图片附件 + 一段使用约束 |
| 4 | 记日志 `[screen] 已截取屏幕 44KB → private:...` |

附进 prompt 的那段话是硬约束：

> 看到能聊的东西就拿它开个话头——但要像「刚好想到」那样自然，**别说「我看到你屏幕」**。
> 屏幕上的私密内容（密码、聊天记录、证件、别人的隐私）**绝不要说出口，也绝不转发到任何群**。

### 3.4 五条安全约束

1. **只对主人的私聊**（`onlyOwnerPrivate: true`）——屏幕内容绝不进群；
2. 图片路径白名单：只允许读 `state/` 目录内的文件（防变成任意读文件的通道）；
3. 最小间隔 5 分钟，不刷屏；
4. 截图进程 20 秒超时 + busy 锁防并发；
5. 提示词明令禁止泄露隐私内容。

**任何失败（锁屏 / 无交互桌面 / 超时）只是不附图片，不影响唤醒本身。**

### 3.5 参数（`config.json` 的 `screen`）

```json
"screen": {
  "enabled": true,            // 总开关
  "onlyOwnerPrivate": true,   // 只截主人的私聊
  "minIntervalMs": 300000,    // 最小间隔 5 分钟
  "maxWidth": 1440,           // 缩放宽度
  "quality": 60,              // JPEG 质量
  "archiveDir": "D:\\鲸鱼娘的查岗记录",
  "archiveMaxFiles": 500,
  "minUsefulBytes": 15000     // 小于此值视为锁屏，不附给她
}
```

### 3.6 相关函数

| 函数 | 位置 |
|---|---|
| `screenAllowedFor()` | `src/bridge.js` |
| `captureScreen()` | `src/bridge.js`（起 `scripts/capture-screen.ps1`） |
| `archiveScreenShot()` | `src/bridge.js` |
| 图片注入进 prompt | `sendWakePromptV2()` 里，仅 `reason === 'proactiveCheck'` |

## 5. 出问题先看哪

| 症状 | 先看 |
|---|---|
| 她不理人 | `state/bridge.log` 搜「忽略未授权会话」（没放行）/「未到门槛」（概率没中）；控制台活动流 |
| 消息重复发 | 日志搜 `[dedupe]`；"结果未知"的网络失败会登记 |
| 截屏只有半屏 | 脚本输出里的 `raw` 尺寸与 `dpi=` 字段 |
| 收不到截图存档 | 看 `screen.archiveDir` 目录本身（日志里路径会被脱敏成 `***`） |
| DSH 连不上 | 检查 DSH 是否在 `127.0.0.1:3080`；`config.dsh` 的地址 |
| 启动就退出 | `state\launcher.out.log` / `bridge.log` 尾部 |

> 日志时间是 **UTC**，且行内只有 `HH:mm:ss` 没有日期——对时间时记得 +8。
